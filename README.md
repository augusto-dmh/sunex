# Sunex

Open-source people management for Brazilian companies, with an employment history you can trust
and AI agents you can audit.

> An HR team opens Sunex and every person's employment history is there as a sequence of dated
> facts: when each change takes effect, when it was recorded, why it happened and who approved it.
> Férias are requested, checked against the CLT and approved in the same place, and the payroll
> system receives clean, signed lifecycle events instead of spreadsheets. Leaders see their people
> through the same rules as everyone else, and AI agents work beside them as accountable users:
> each one has an owner, acts within a scope, asks a human before it changes anything, and leaves a
> record of every action.

## Status

**Pre-alpha: design complete, implementation starting.** The repository holds the Laravel 13
starter-kit scaffold plus the foundation documents. Nothing here is usable by an HR team yet.

| | |
|---|---|
| Current phase | v1 (12-week appetite): bitemporal employment record, org and positions, movements with approvals, férias and afastamentos, eSocial readiness and signed events, agent registry + MCP, two agents |
| Plan | [TDD-0001](docs/tdd/0001-v1-architecture.md) phases → [roadmap rows](.specs/project/ROADMAP.md) |
| Next rows | see the Handoff section of [STATE.md](.specs/project/STATE.md) |

What Sunex will **not** do, in any phase: calculate payroll, generate eSocial XML or transmit to
eSocial ([ADR-0009](docs/adr/0009-no-payroll-no-esocial-transmission.md)). The payroll system stays
the transmitter; Sunex is the best-structured source of the facts it needs.

## Stack

| Layer | Choice | Why |
|---|---|---|
| Backend | Laravel 13, PHP 8.4 | [ADR-0002](docs/adr/0002-laravel-13-php-84-postgresql.md) |
| Database | PostgreSQL 17 + pgvector | Range types and exclusion constraints keep effective-dated rows from overlapping ([ADR-0005](docs/adr/0005-bitemporal-employment-versions.md)) |
| Frontend | Inertia 3, Vue 3, TypeScript, Tailwind 4 | [ADR-0003](docs/adr/0003-inertia-vue-typescript-frontend.md) |
| Auth | Fortify (session + passkeys); Passport OAuth 2.1 for MCP clients | [ADR-0007](docs/adr/0007-agents-as-principals-one-toolset.md) |
| Agents | `laravel/ai` 1.x + `laravel/mcp` 1.x in-process, behind an `AgentRuntime` port | [ADR-0008](docs/adr/0008-agent-runtime-laravel-ai-and-mcp.md) |
| Quality | Pest 5 (unit, feature, architecture, browser), Larastan, Pint, Rector | [CONTRIBUTING.md](CONTRIBUTING.md) |

## Run locally

Requirements: PHP 8.4 with the `pdo_pgsql` extension, Composer 2, Node 22+, Docker.

```bash
# 1. PostgreSQL 17 with pgvector on a non-default host port
docker run -d --name sunex-pg -p 54329:5432 \
  -e POSTGRES_USER=sunex -e POSTGRES_PASSWORD=sunex -e POSTGRES_DB=sunex \
  pgvector/pgvector:pg17

# 2. Environment: point the app at that database
cp .env.example .env
#   DB_PORT=54329  DB_USERNAME=sunex  DB_PASSWORD=sunex

# 3. Install, generate the key, migrate and build assets
composer setup

# 4. Run the app, queue worker, logs and Vite together
composer dev        # http://localhost:8000
```

Checks before a pull request:

```bash
composer test       # config clear, lint check, type check, Pest
```

The first roadmap row (`postgres-platform`) replaces step 1 with a committed Compose file, and the
demo row turns steps 1–3 into one command with a seeded demo company group.

## Language

The code, documentation, commits and pull requests are in English. Brazilian legal terms (férias,
afastamento, CLT, eSocial, CNPJ) stay in Portuguese and are explained where they first appear. The
UI copy is English behind translation keys; a pt-BR locale is a planned roadmap row
([ADR-0012](docs/adr/0012-english-ui-copy-behind-translation-keys.md)).

## Disclaimer

Sunex calculates férias balances and statutory deadlines to help HR teams, but it is not legal
advice and not a payroll system. The payroll system remains the system of record for payment and
for everything sent to eSocial.
